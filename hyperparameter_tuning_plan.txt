2.1 STANDARD DE (de.py)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
Classic Differential Evolution with DE/rand/1/bin strategy. This is the
baseline implementation from Nathan Rooy's simple DE algorithm.

Mutation: child = x_rand1 + F * (x_rand2 - x_rand3)
Selection: Uses uniform crossover with probability CR

This serves as the baseline for comparison with more advanced DE variants.

TUNABLE HYPERPARAMETERS:
-------------------------

1. mutate (F) - Mutation Scaling Factor
   Type: float
   Default: 0.5
   Description: Controls the amplification of differential variation between
                individuals. Higher values increase exploration and diversity,
                while lower values favor exploitation and convergence.
   Impact: CRITICAL - Most important DE parameter
   Typical behavior:
     - F < 0.4: Slow convergence, risk of premature stagnation
     - F = 0.4-0.6: Balanced exploration/exploitation
     - F = 0.6-0.8: More explorative, better for complex landscapes
     - F > 1.0: Very exploratory, risk of instability

2. recombination (CR) - Crossover Probability
   Type: float
   Default: 0.9
   Description: Probability that a dimension is inherited from the mutant
                (donor) vector rather than the target vector. Higher values
                mean more dimensions are taken from the donor, increasing
                diversity. Lower values preserve more of the target.
   Impact: HIGH - Controls balance between parent and donor inheritance
   Typical behavior:
     - CR < 0.5: More conservative, slow mixing
     - CR = 0.7-0.9: Recommended for most problems
     - CR > 0.95: Aggressive mixing, can be unstable

RECOMMENDED SEARCH SPACES:
--------------------------

mutate (F):
  - Range: [0.4, 1.0]
  - Distribution: Log-uniform (log=True)
  - Justification: Most literature recommends 0.4-0.8; we extend to 1.0 to
                   explore more aggressive values. Log-scale because the
                   difference between 0.4 and 0.5 is more significant than
                   between 0.9 and 1.0.

recombination (CR):
  - Range: [0.7, 0.95]
  - Distribution: Uniform
  - Justification: Values below 0.7 typically underperform; 0.9 is most common
                   recommendation. We explore 0.7-0.95 to find optimal balance.

OPTUNA CODE EXAMPLE:
--------------------

def suggest_hyperparameters_de(trial):
    """Suggest hyperparameters for Standard DE."""
    return {
        'mutate': trial.suggest_float('mutate', 0.4, 1.0, log=True),
        'recombination': trial.suggest_float('recombination', 0.7, 0.95)
    }

IMPLEMENTATION NOTES:
---------------------
- READY TO TUNE: de.py already accepts both parameters
- No code modifications needed
- Simply pass suggested values to minimize() function
- Current defaults in search_control.py: F=0.5, CR=0.9

PARAMETER INTERACTION:
----------------------
- High F + High CR: Maximum exploration (good for multimodal)
- Low F + Low CR: Maximum exploitation (good near optimum)
- High F + Low CR: Aggressive mutation, conservative crossover
- Low F + High CR: Conservative mutation, aggressive crossover

LITERATURE RECOMMENDATIONS:
---------------------------
- Price et al. (2005): F=0.5, CR=0.9 (default values)
- Storn & Price (1997): F in [0.5, 1.0], CR in [0.8, 1.0]
- Das & Suganthan (2011): F=0.5, CR=0.9 for most problems

2.2 EVOX ODE (Oppositional Differential Evolution)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
ODE extends standard DE with opposition-based learning. It simultaneously
considers both a candidate solution and its opposite point in the search space,
which can accelerate convergence by better exploring the landscape.

Key innovation: For a point x in [lb, ub], the opposite point is:
  x_opposite = lb + ub - x

ODE uses opposition for initialization and generation jumping (periodic
evaluation of opposite population).

Reference: Rahnamayan et al. (2008), IEEE TEC 12(1):64-79
Documentation: https://evox.readthedocs.io/en/latest/apidocs/evox/evox.algorithms.so.de_variants.ode.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. base_vector - Mutation Base Vector Strategy
   Type: str (categorical)
   Default: 'rand'
   Options: ['best', 'rand']
   Description: Determines which vector serves as the base for mutation.
     - 'rand': Uses a randomly selected individual (DE/rand strategy)
               More exploratory, better for multimodal landscapes
     - 'best': Uses the current best individual (DE/best strategy)
               More exploitative, faster convergence but higher risk of
               premature convergence
   Impact: HIGH - Fundamentally changes search behavior

2. num_difference_vectors - Number of Difference Vectors
   Type: int (categorical)
   Default: 1
   Options: [1, 2]
   Constraint: Must be < popsize/2 (with popsize=600, max is 299, so 1-2 safe)
   Description: Number of difference vectors used in mutation.
     - 1: Classic DE mutation: base + F*(x1 - x2)
          Simpler, more stable, computationally cheaper
     - 2: Extended mutation: base + F*(x1 - x2) + F*(x3 - x4)
          More diversity, better for high-dimensional problems
   Impact: MEDIUM - Affects exploration diversity

3. differential_weight (F) - Mutation Scaling Factor
   Type: float
   Default: 0.5
   Description: Amplification factor for difference vectors. Same role as
                mutate parameter in standard DE. Controls exploration vs
                exploitation balance.
   Impact: CRITICAL - Most sensitive parameter

4. cross_probability (CR) - Crossover Probability
   Type: float
   Default: 0.9
   Constraint: Must be > 0.0
   Description: Probability of inheriting dimension from donor vector.
                Equivalent to recombination in standard DE.
   Impact: HIGH - Controls genetic mixing

RECOMMENDED SEARCH SPACES:
--------------------------

base_vector:
  - Options: ['best', 'rand']
  - Justification: Try both strategies; problem-dependent which is better

num_difference_vectors:
  - Options: [1, 2]
  - Justification: More than 2 adds complexity without much benefit for
                   popsize=600. Literature typically uses 1-2.

differential_weight (F):
  - Range: [0.4, 1.0]
  - Distribution: Log-uniform (log=True)
  - Justification: Same as standard DE; opposition-based learning benefits
                   from slightly higher F for exploration

cross_probability (CR):
  - Range: [0.7, 0.95]
  - Distribution: Uniform
  - Justification: Must be > 0 (constraint); standard DE recommendations apply

--------------------

2.3 EVOX CODE (Composite Differential Evolution)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
CoDE combines three DE mutation strategies with three parameter settings in a
composite trial vector generation framework. It uses a pool of control
parameter pairs (F, CR) and randomly selects from them, which provides
automatic parameter adaptation without learning.

Three strategies used:
  1. rand/1/bin: x_base = random, 1 difference vector
  2. rand/2/bin: x_base = random, 2 difference vectors
  3. current-to-rand/1: x_base = current, directed toward random

Three default (F, CR) pairs:
  1. (1.0, 0.1) - High mutation, low crossover
  2. (1.0, 0.9) - High mutation, high crossover
  3. (0.8, 0.2) - Moderate mutation, low crossover

Reference: Wang et al. (2011), IEEE TEC 15(1):55-66
Documentation: https://evox.readthedocs.io/en/latest/apidocs/evox/evox.algorithms.so.de_variants.code.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. diff_padding_num - Differential Padding Number
   Type: int
   Default: 5
   Description: Number of differential padding vectors for diversity maintenance.
                Padding adds extra difference vectors to trial generation to
                enhance population diversity and prevent premature convergence.
                Higher values increase computational cost but improve diversity.
   Impact: MEDIUM-HIGH - Affects exploration capacity
   Typical behavior:
     - Low (3-5): Less diverse, faster convergence
     - Medium (6-10): Balanced diversity
     - High (>10): Very diverse, slower convergence

2. param_pool (ADVANCED) - Control Parameter Pool
   Type: tensor of (F, CR) pairs
   Default: [[1.0, 0.1], [1.0, 0.9], [0.8, 0.2]]
   Description: Pool of (F, CR) parameter combinations. CoDE randomly selects
                one pair for each trial vector generation. The pool represents
                different exploration/exploitation strategies.
   Impact: HIGH - But complex to tune (6 sub-parameters)
   Note: For simplicity, we recommend tuning only diff_padding_num first.
         Advanced tuning can optimize the (F, CR) pairs themselves.

3. replace - Population Replacement Strategy
   Type: bool
   Default: False
   Description: Whether to allow replacement of individuals in population.
     - False: Standard greedy selection (child replaces parent only if better)
     - True: Alternative replacement strategy
   Impact: LOW - Usually False works well

RECOMMENDED SEARCH SPACES:
--------------------------

SIMPLE APPROACH (Recommended for first tuning):
------------------------------------------------

diff_padding_num:
  - Range: [3, 10]
  - Distribution: Uniform integer
  - Justification: Default is 5; explore 3-10 to find optimal diversity level

replace:
  - Options: [True, False]
  - Justification: Test both strategies, though False is standard

ADVANCED APPROACH (Optional second tuning):
--------------------------------------------

If simple tuning works well, you can then tune the param_pool by tuning
6 parameters (three F values, three CR values):

F1, F2, F3:
  - Range: [0.5, 1.2]
  - Description: Three mutation factors for param_pool

CR1, CR2, CR3:
  - Range: [0.1, 0.95]
  - Description: Three crossover rates for param_pool

Then construct: param_pool = [[F1, CR1], [F2, CR2], [F3, CR3]]

OPTUNA CODE EXAMPLE (SIMPLE):
------------------------------

def suggest_hyperparameters_code(trial):

    return {
        'diff_padding_num': trial.suggest_int('diff_padding_num', 3, 10),

    # Tune the three (F, CR) pairs

2.4 EVOX SHADE (Success-History based Adaptive Differential Evolution)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
SHADE improves upon JADE by maintaining a historical memory of successful
parameter values. Instead of adapting F and CR individually, SHADE stores
successful (F, CR) pairs in a memory and samples from this memory for
parameter generation, using weighted Lehmer mean for updating.

Key innovation: Historical memory M_F and M_CR store successful parameters
  - Memory size H (typically popsize or larger)
  - Successful parameters from generation t update memory
  - New parameters sampled from memory using Cauchy/Normal distributions

SHADE automatically adapts F and CR, making it largely parameter-free.

Reference: Tanabe & Fukunaga (2013), IEEE CEC pp. 71-78
Documentation: https://evox.readthedocs.io/en/latest/apidocs/evox/evox.algorithms.so.de_variants.shade.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. diff_padding_num - Differential Padding Number
   Type: int
   Default: 9
   Description: Number of differential padding vectors for trial generation.
                Controls diversity in mutation by adding extra difference
                vectors. SHADE uses current-to-pbest mutation strategy with
                padding for enhanced exploration.
   Impact: MEDIUM - Primary tunable parameter
   Typical behavior:
     - Low (5-7): Faster convergence, less diverse
     - Medium (8-10): Balanced (default=9 from paper)
     - High (11-15): More diverse, slower initial convergence

NOTE ON LIMITED PARAMETERS:
---------------------------
SHADE has very few tunable parameters because:
- F and CR are adapted automatically via success-history mechanism
- Memory size H is internally set (typically = popsize)
- Mutation strategy is fixed (current-to-pbest/1)
- The algorithm is designed to be largely parameter-free

This makes SHADE easier to tune but also less flexible than other variants.

RECOMMENDED SEARCH SPACES:
--------------------------

diff_padding_num:
  - Range: [5, 15]
  - Distribution: Uniform integer
  - Justification: Default is 9; explore ±50% range to find optimal diversity
                   level for TSP/CVRP latent space optimization

ADVANTAGES OF SHADE:
--------------------
- Automatic parameter adaptation (no need to tune F, CR)
- Robust across different problem types
- Success-history mechanism learns from good parameter values
- Generally outperforms basic JADE on complex problems

DISADVANTAGES:
--------------
- Limited tunability (only one main parameter)
- Slightly more memory overhead (stores history)
- May be overkill for simple problems where static F, CR work well

WHEN TO USE SHADE:
------------------
- When you want automatic parameter adaptation
- For complex, multimodal optimization landscapes
- When you don't want to manually tune F and CR
- As a robust "set and forget" option

2.5 EVOX SADE (Self-adaptive Differential Evolution)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
SaDE adapts both mutation strategy selection and CR parameter during evolution.
It maintains a pool of four DE mutation strategies and learns which strategies
work best through a probability-based selection mechanism.

Four strategies in pool:
  1. DE/rand/1/bin
  2. DE/rand/2/bin
  3. DE/rand-to-best/2/bin
  4. DE/current-to-rand/1

Strategy probabilities are updated based on success rates, and CR values are
adapted using Normal distribution sampling from a memory of successful CRs.

Reference: Qin & Suganthan (2005), IEEE CEC Vol. 2, pp. 1785-1791
Documentation: https://evox.readthedocs.io/en/latest/apidocs/evox/evox.algorithms.so.de_variants.sade.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. diff_padding_num - Differential Padding Number
   Type: int
   Default: 9
   Description: Number of differential padding vectors for diversity.
                Similar role as in SHADE - controls exploration capacity
                by adding extra difference vectors to mutation.
   Impact: MEDIUM-HIGH - Affects population diversity

2. LP - Learning Period (Memory Size)
   Type: int
   Default: 50
   Description: Size of the memory window for adaptation. Controls how many
                generations of history are used to adapt:
                  - CR value distribution
                  - Strategy selection probabilities
                Smaller LP = faster adaptation to recent trends
                Larger LP = more stable adaptation based on longer history
   Impact: MEDIUM - Controls adaptation speed
   Typical behavior:
     - Low (20-40): Fast adaptation, responsive to recent success
     - Medium (50-70): Balanced adaptation (default from paper)
     - High (80-100): Slow adaptation, more stable probabilities

RECOMMENDED SEARCH SPACES:
--------------------------

diff_padding_num:
  - Range: [5, 15]
  - Distribution: Uniform integer
  - Justification: Same as SHADE; explore around default of 9

LP (Learning Period):
  - Range: [30, 100]
  - Distribution: Uniform integer
  - Justification: Default is 50; explore range to balance adaptation speed
                   vs stability. With 75s time limit and popsize=600,
                   we expect ~50-150 generations, so LP in [30,100] is
                   reasonable to capture learning.

ADVANTAGES OF SADE:
-------------------
- Automatic strategy selection (learns which DE variant works best)
- Automatic CR adaptation

2.6 STANDARD CMA-ES
================================================================================

ALGORITHM DESCRIPTION:
----------------------
Covariance Matrix Adaptation Evolution Strategy (CMA-ES) is a state-of-the-art
continuous optimization algorithm. Unlike DE which uses differences between
individuals, CMA-ES maintains and adapts a full covariance matrix to model
promising search directions.

Key components:
  - Mean vector: Center of search distribution
  - Step size (sigma): Controls exploration radius
  - Covariance matrix C: Models correlations between dimensions
  - Evolution paths: Track successful search directions

CMA-ES is particularly effective for ill-conditioned and non-separable problems.

Reference: Hansen & Ostermeier (2001), Evolutionary Computation 9(2):159-195
Documentation: https://github.com/CMA-ES/pycma
API Docs: https://cma-es.github.io/apidocs-pycma/cma.options_parameters.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. sigma0 - Initial Step Size
   Type: float
   Default: 0.5
   Description: Initial standard deviation (step size) for the search
                distribution. Controls the initial exploration radius.
                Typically set to 0.2-0.5 of the search range.

                With search_space_bound = B, search range is [-B, +B] = 2B.
                sigma0 = 0.5 means initial std dev is 0.5 * 2B = B.

   Impact: CRITICAL - Most important CMA-ES parameter
   Typical behavior:
     - Too small (< 0.2): Slow convergence, may miss global optimum
     - Optimal (0.2-0.5): Fast convergence to quality solutions
     - Too large (> 0.8): Unstable, excessive exploration

   NOTE: CMA-ES adapts sigma during evolution, but initial value affects
         early search behavior and convergence speed.

2. use_lhs - Use Latin Hypercube Sampling for Initialization
   Type: bool
   Default: True
   Description: Whether to initialize population using Latin Hypercube Sampling
                (LHS) instead of uniform random sampling.

                - True: LHS "primes the pump" with well-distributed initial
                        population, giving CMA-ES better starting distribution
                - False: Standard uniform random initialization at origin

   Impact: MEDIUM - Affects initial search quality

   LHS advantages:
     - Better space coverage in initial population
     - Faster initial convergence
     - More robust to initialization

   When to use False:
     - If you prefer pure CMA-ES behavior (no preprocessing)
     - For benchmarking against standard CMA-ES

ADDITIONAL PARAMETERS (Currently Not Exposed):
-----------------------------------------------

The pycma library supports many advanced options. If initial tuning shows
promise, consider exposing these in a second tuning phase:

- popsize_factor: Multiplier for population size (default: 1.0)
- CSA_dampfac: Damping for step-size adaptation (default: 1.0)
- CMA_rankmu: Learning rate for rank-mu covariance update (default: 1.0)
- CMA_rankone: Learning rate for rank-one covariance update (default: 1.0)

For now, we keep it simple with sigma0 and use_lhs only.

RECOMMENDED SEARCH SPACES:
--------------------------

sigma0:
  - Range: [0.2, 0.8]
  - Distribution: Uniform
  - Justification: Literature recommends 0.2-0.5 of search range. We explore
                   up to 0.8 to test if larger initial exploration helps with
                   multimodal TSP/CVRP latent spaces.

use_lhs:
  - Options: [True, False]
  - Justification: Test whether LHS initialization improves performance.
                   Expect True to be better, but worth confirming.

OPTUNA CODE EXAMPLE:

================================================================================
2.7 IPOP-CMA-ES (Increasing Population CMA-ES)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
IPOP-CMA-ES extends standard CMA-ES with a restart strategy using increasing
population sizes. When CMA-ES converges (based on stopping criteria), it
restarts with a larger population and new random initialization.

Restart strategy:
  - Run 0: popsize = initial_popsize
  - Run 1: popsize = initial_popsize × incpopsize
  - Run 2: popsize = initial_popsize × incpopsize²
  - etc.

Population doubling (incpopsize=2) is standard and recommended in literature.

Key insight: Larger populations are better for multimodal problems but more
expensive. IPOP starts small (cheap exploration) and progressively increases
population (broader exploration) if needed.

Reference: Auger & Hansen (2005), GECCO pp. 415-422
Documentation: https://cma-es.github.io/apidocs-pycma/

TUNABLE HYPERPARAMETERS:
-------------------------

1. sigma0 - Initial Step Size
   Type: float
   Default: 0.5
   Description: Initial step size for each restart. Same role as in standard
                CMA-ES. Each restart begins with this sigma0 value.
   Impact: CRITICAL - Affects all restarts

2. restarts - Number of Restarts
   Type: int
   Default: 5
   Description: Number of times to restart CMA-ES with increased population.
                Total runs = restarts + 1 (initial run + restart runs).

                With restarts=5 and incpopsize=2.0:
                  - Run 0: popsize = 600
                  - Run 1: popsize = 1200
                  - Run 2: popsize = 2400
                  - Run 3: popsize = 4800
                  - Run 4: popsize = 9600
                  - Run 5: popsize = 19200

   Impact: HIGH - More restarts = more exploration but higher cost

   Typical behavior:
     - Low (3-4): Faster, less thorough exploration
     - Medium (5-6): Balanced (default)
     - High (7-10): Very thorough, expensive

3. incpopsize - Population Size Multiplier
   Type: float
   Default: 2.0
   Description: Factor by which population size increases with each restart.
                Standard IPOP-CMA-ES uses 2.0 (population doubling).

                Smaller values (1.5) = more gradual increase, more restarts
                Larger values (2.5+) = aggressive increase, fewer restarts

   Impact: HIGH - Controls restart aggressiveness

   Typical values:
     - Conservative (1.5): Gradual scaling, many small restarts
     - Standard (2.0): Population doubling (recommended)
     - Aggressive (2.5): Faster scaling, fewer large restarts

4. use_lhs - Use Latin Hypercube Sampling for First Run
   Type: bool
   Default: True
   Description: Whether to use LHS initialization for the FIRST run only.
                Subsequent restarts use standard random initialization.

                Rationale: LHS helps first run converge faster. Restarts
                explore different regions, so random init is appropriate.

   Impact: MEDIUM - Affects initial search quality only

RECOMMENDED SEARCH SPACES:
--------------------------

sigma0:
  - Range: [0.2, 0.8]
  - Distribution: Uniform
  - Justification: Same as standard CMA-ES

restarts:
  - Range: [3, 8]
  - Distribution: Uniform integer
  - Justification: With 75s limit, fewer than 3 restarts may not benefit from
                   IPOP strategy. More than 8 may not complete within time.
                   Consider computational budget:
                   - More restarts = more exploration
                   - But each restart after ~3-4 has huge population

incpopsize:
  - Range: [1.5, 2.5]
  - Distribution: Uniform
  - Justification: Literature recommends 2.0. We explore ±25% to test if
                   more gradual (1.5) or aggressive (2.5) scaling works better.

use_lhs:
  - Options: [True, False]
  - Justification: Test both; expect True to be better

================================================================================
2.8 BIPOP-CMA-ES (Bi-Population CMA-ES)
================================================================================

ALGORITHM DESCRIPTION:
----------------------
BIPOP-CMA-ES extends IPOP-CMA-ES by alternating between two types of restarts:
  1. Large population restarts (IPOP-style): For exploitation
  2. Small population restarts: For exploration

Budget management ensures balanced use of both restart types.

Restart strategy:
  - Large population (IPOP): popsize × incpopsize, standard sigma
  - Small population: random popsize (~0.5-1.0 × initial), varied sigma

Algorithm alternates between small runs (exploration) until budget_small ≥
budget_large, then does a large run (exploitation) with increased population.

Key insight: Small populations with varied parameters explore more diverse
regions of the search space, while large populations exploit promising regions.
This combination is more robust than pure IPOP.

Reference: Hansen (2009), GECCO pp. 455-462
Documentation: https://cma-es.github.io/apidocs-pycma/

TUNABLE HYPERPARAMETERS:
-------------------------

1. sigma0 - Initial Step Size for Large Populations
   Type: float
   Default: 0.5
   Description: Initial step size for large population restarts. Small
                population restarts use randomized sigma (sigma0 × [0.5-1.5])
                for exploration.
   Impact: CRITICAL - Baseline for all restarts

2. restarts - Total Number of Restarts
   Type: int
   Default: 5
   Description: Total number of restarts (alternating between small and large).
                The algorithm automatically decides when to do small vs large
                restarts based on budget management.

                Typical sequence (simplified):
                  - Run 0: Initial (large, popsize=600)
                  - Run 1: Small (popsize~400, varied sigma)
                  - Run 2: Small (popsize~500, varied sigma)
                  - Run 3: Large (popsize=1200, standard sigma)
                  - Run 4: Small (popsize~300, varied sigma)
                  - etc.

   Impact: HIGH - More restarts = more exploration of small/large balance

3. incpopsize - Population Size Multiplier for Large Restarts
   Type: float
   Default: 2.0
   Description: Factor by which large population increases (IPOP-style).
                Small populations are sized randomly (~0.5-1.0 × initial popsize)
                and NOT affected by this parameter.
   Impact: HIGH - Controls large restart aggressiveness

4. use_lhs - Use Latin Hypercube Sampling for First Run
   Type: bool
   Default: True
   Description: Whether to use LHS initialization for the FIRST run only.
                Subsequent restarts (both small and large) use random init.
   Impact: MEDIUM - Affects initial search quality

RECOMMENDED SEARCH SPACES:
--------------------------

sigma0:
  - Range: [0.2, 0.8]
  - Distribution: Uniform
  - Justification: Same as IPOP-CMA-ES; serves as baseline for both small
                   and large restarts

restarts:
  - Range: [3, 8]
  - Distribution: Uniform integer
  - Justification: Same as IPOP-CMA-ES; need sufficient restarts to benefit
                   from bi-population strategy

incpopsize:
  - Range: [1.5, 2.5]
  - Distribution: Uniform
  - Justification: Same as IPOP-CMA-ES; controls large restart scaling

use_lhs:
  - Options: [True, False]
  - Justification: Test both; expect True to be better

================================================================================
2.9 SCIPY DIFFERENTIAL EVOLUTION
================================================================================

ALGORITHM DESCRIPTION:
----------------------
SciPy's differential_evolution is a feature-rich DE implementation with many
strategies and adaptive mechanisms. It includes:
  - Multiple mutation strategies (best/rand, 1/2 diff vectors, etc.)
  - Adaptive parameter dithering (F varies each generation)
  - Multiple initialization methods (Latin Hypercube, Sobol, Halton, random)
  - Synchronous (deferred) or asynchronous (immediate) updating

Current implementation uses:
  - strategy='best1bin' (DE/best/1/bin)
  - mutation=(0.5, 1.0): Adaptive dithering - F ∈ [0.5, 1.0] random each gen
  - recombination=0.9: Fixed high crossover
  - init='latinhypercube': LHS initialization
  - updating='deferred': Classic synchronous DE

Reference: SciPy documentation
Documentation: https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.differential_evolution.html

TUNABLE HYPERPARAMETERS:
-------------------------

1. strategy - DE Mutation Strategy
   Type: str (categorical)
   Default: 'best1bin'
   Description: Differential evolution strategy. Format: base/num_vectors/crossover

   Available strategies:

   a) 'best1bin': DE/best/1/bin
      - Base: Current best individual
      - Mutation: best + F*(x1 - x2)
      - Crossover: Binomial
      - Behavior: Fast convergence, exploitative, risk of premature convergence

   b) 'best1exp': DE/best/1/exp
      - Same as best1bin but with exponential crossover
      - Crossover: Exponential (consecutive dimensions)
      - Behavior: Similar to best1bin but different mixing

   c) 'rand1bin': DE/rand/1/bin
      - Base: Random individual
      - Mutation: rand + F*(x1 - x2)
      - Crossover: Binomial
      - Behavior: More explorative, robust, slower convergence

   d) 'rand1exp': DE/rand/1/exp
      - Same as rand1bin but with exponential crossover

   e) 'rand2bin': DE/rand/2/bin
      - Mutation: rand + F*(x1 - x2) + F*(x3 - x4)
      - Uses 2 difference vectors
      - Behavior: Very diverse, good for multimodal

   f) 'rand2exp': DE/rand/2/exp
      - Same as rand2bin but with exponential crossover

   g) 'best2bin': DE/best/2/bin
      - Base: Best individual, 2 difference vectors
      - Mutation: best + F*(x1 - x2) + F*(x3 - x4)
      - Behavior: Exploitative with high diversity

   h) 'best2exp': DE/best/2/exp
      - Same as best2bin but with exponential crossover

   i) 'randtobest1bin': DE/rand-to-best/1/bin
      - Mutation: rand + F*(best - rand) + F*(x1 - x2)
      - Behavior: Balanced exploration/exploitation

   j) 'randtobest1exp': DE/rand-to-best/1/exp
      - Same as randtobest1bin but with exponential crossover

   k) 'currenttobest1bin': DE/current-to-best/1/bin
      - Mutation: current + F*(best - current) + F*(x1 - x2)
      - Behavior: Directed toward best, adaptive to current position

   l) 'currenttobest1exp': DE/current-to-best/1/exp
      - Same as currenttobest1bin but with exponential crossover

   Impact: CRITICAL - Fundamentally changes algorithm behavior

   Recommended subset for tuning (to keep search manageable):
     - 'best1bin': Fast, exploitative (current default)
     - 'rand1bin': Robust, explorative
     - 'randtobest1bin': Balanced
     - 'currenttobest1bin': Adaptive

2. mutation (F) - Mutation Factor
   Type: float OR tuple of (min, max)
   Default: (0.5, 1.0)
   Description: Differential weight for mutations.

   Two modes:

   a) Fixed F (float):
      - Single value used for all generations
      - Example: mutation=0.8
      - Behavior: Consistent exploration level

   b) Adaptive dithering (tuple):
      - F randomly sampled from [min, max] each generation
      - Example: mutation=(0.5, 1.0)
      - Behavior: Variable exploration, more robust
      - Current default in scipy_de.py

   Impact: CRITICAL - Controls exploration vs exploitation

   Typical values:
     - Conservative fixed: 0.5
     - Standard fixed: 0.8
     - Aggressive fixed: 1.0
     - Dithering ranges: (0.5, 1.0), (0.3, 1.2), (0.4, 0.9)

3. recombination (CR) - Crossover Probability
   Type: float
   Default: 0.9
   Description: Probability of taking dimension from donor vector.
                Standard DE parameter. SciPy only supports fixed CR
                (not tuple/dithering like mutation).
   Impact: HIGH - Controls genetic mixing
   Range: (0.0, 1.0]

4. init - Population Initialization Method
   Type: str (categorical)
   Default: 'latinhypercube'
   Description: Method for generating initial population.

   Options:

   a) 'latinhypercube': Latin Hypercube Sampling
      - Stratified sampling ensuring good space coverage
      - Each dimension divided into equal intervals, one sample per interval
      - Best for exploration, recommended default

   b) 'sobol': Sobol low-discrepancy sequence
      - Quasi-random sequence with excellent uniformity
      - Better than random for multi-dimensional spaces
      - Good theoretical properties

   c) 'halton': Halton low-discrepancy sequence
      - Another quasi-random sequence
      - Similar benefits to Sobol
      - May have edge on very high dimensions

   d) 'random': Uniform random sampling
      - Standard random initialization
      - Baseline comparison
      - Least structured, most random

   Impact: MEDIUM - Affects initial search quality and early convergence

   Expected ranking: latinhypercube ≥ sobol ≥ halton > random

5. updating - Population Update Strategy
   Type: str (categorical)
   Default: 'deferred'
   Description: When to update population with trial vectors.

   Options:

   a) 'deferred': Synchronous (Classic DE)
      - Evaluate entire population of trial vectors
      - Update entire population at once after all evaluations
      - Population changes generation-by-generation
      - Advantage: Stable, well-studied, easier to analyze

   b) 'immediate': Asynchronous
      - Update population immediately when trial is better
      - Trial vectors see updated population during same generation
      - More greedy, faster convergence
      - Advantage: Uses most recent information, can converge faster
      - Disadvantage: Less theoretical foundation, order-dependent

   Impact: MEDIUM - Affects convergence dynamics

   'deferred' is standard DE; 'immediate' can be faster but less stable

RECOMMENDED SEARCH SPACES:
--------------------------

strategy:
  - Options: ['best1bin', 'rand1bin', 'randtobest1bin', 'currenttobest1bin']
  - Justification: These 4 cover the main strategy types (best-based, rand-based,
                   hybrid). Full 12-strategy search would be inefficient.
                   Can expand if results suggest benefit.

    - Distribution: Uniform

    - Two parameters: mutation_low, mutation_high
    - mutation_low range: [0.3, 0.7]
    - mutation_high range: [0.8, 1.5]
    - Construct: mutation = (mutation_low, mutation_high)

  Use conditional suggestion in Optuna (see code example)

recombination:
  - Range: [0.7, 0.95]
  - Distribution: Uniform
  - Justification: Standard DE recommendation

  - Options: ['latinhypercube', 'sobol', 'halton', 'random']
  - Justification: Test all initialization methods

  - Options: ['deferred', 'immediate']
  - Justification: Test both update strategies

def suggest_hyperparameters_scipy_de(trial):
    """Suggest hyperparameters for SciPy Differential Evolution."""

    # 1. Strategy selection
    strategy = trial.suggest_categorical('strategy',
        ['best1bin', 'rand1bin', 'randtobest1bin', 'currenttobest1bin'])

    # 2. Mutation: Choose between fixed and adaptive dithering
    use_adaptive_mutation = trial.suggest_categorical('use_adaptive_mutation',
                                                       [True, False])
    if use_adaptive_mutation:
        # Adaptive dithering: F ∈ [mutation_low, mutation_high]
        mutation_low = trial.suggest_float('mutation_low', 0.3, 0.7)
        mutation_high = trial.suggest_float('mutation_high', 0.8, 1.5)
        # Ensure mutation_low < mutation_high
        if mutation_low >= mutation_high:
            mutation_high = mutation_low + 0.2
        mutation = (mutation_low, mutation_high)
    else:
        # Fixed F
        mutation = trial.suggest_float('mutation_fixed', 0.5, 1.0)

    # 3. Recombination (crossover probability)
    recombination = trial.suggest_float('recombination', 0.7, 0.95)

    # 4. Initialization method
    init = trial.suggest_categorical('init',
        ['latinhypercube', 'sobol', 'halton', 'random'])

    # 5. Update strategy
    updating = trial.suggest_categorical('updating', ['deferred', 'immediate'])

    return {
        'strategy': strategy,
        'mutation': mutation,
        'recombination': recombination,
        'init': init,
        'updating': updating
    }

SEARCH SPACE TIPS:
------------------

1. Use log-scale for parameters spanning orders of magnitude:
   - Example: trial.suggest_float('param', 0.01, 1.0, log=True)
   - Good for: F, learning rates, small scale parameters

2. Use uniform for bounded continuous parameters:
   - Example: trial.suggest_float('param', 0.0, 1.0)
   - Good for: CR, probabilities, sigma values

3. Use categorical for discrete choices:
   - Example: trial.suggest_categorical('param', ['opt1', 'opt2'])
   - Good for: Strategies, boolean options, discrete integer choices

4. Use int for discrete numeric parameters:
   - Example: trial.suggest_int('param', 1, 10)
   - Good for: Population sizes, memory sizes, iteration counts

   - Increase to 75-100 trials for complex search spaces

2. Search space too wide:
   - Narrow ranges based on literature
   - Use log-scale where appropriate

   - Try different subset of tuning instances
   - Ensure instances are representative

4. Time limit too restrictive:
   - If optimizer rarely completes iterations, increase time
   - Or reduce search space size

5. Optuna not converging:
   - Check TPE sampler is being used
   - Ensure seed is set for reproducibility
   - View optimization history plot to diagnose

SCRIPT TEMPLATE:
----------------

Use optuna_jade_tune.py as template for creating other tuning scripts.

Key sections to adapt:

1. Import optimizer module:
   ```python
   import <optimizer_module>  # e.g., import de, import cmaes, etc.
   ```

2. Define create_config_for_trial():
   ```python
   def create_config_for_trial(base_config, **optimizer_params):
       # Set optimizer-specific parameters on config
       config.optimizer = '<optimizer_name>'
       config.<param1> = optimizer_params['param1']
       # ... etc
       return config
   ```

3. Define objective() function:
   ```python
   def objective(trial: optuna.Trial, args) -> float:
       # Suggest hyperparameters
       param1 = trial.suggest_float('param1', min_val, max_val)
       # ...

       # Create config
       config = create_config_for_trial(base_config, param1=param1, ...)

       # Evaluate on tuning instances
       gaps = []
       for instance in tuning_instances:
           objective_value, solution, ... = solve_instance(
               model, instance, config, cost_fn, batch_size)
           gap = calculate_gap(objective_value, optimal_value)
           gaps.append(gap)

       return np.mean(gaps)
   ```

4. Main loop:
   ```python
   study = optuna.create_study(...)
   study.optimize(lambda trial: objective(trial, args), n_trials=50)
   ```

5. Save results:
   ```python
   # Save best params to JSON
   # Generate visualizations
   # Log summary
   ```

DEBUGGING TIPS:
---------------

Common issues and solutions:

1. "Parameter not found in config":
   - Ensure parameter is added to config in create_config_for_trial()
   - Check search_control.py reads the parameter correctly

2. "Algorithm constructor error":
   - Verify parameter names match algorithm documentation
   - Check parameter types (int vs float, tensor vs scalar)
   - Ensure device is correctly specified

3. "Study already exists":
   - Use --load_if_exists flag to resume
   - Or delete SQLite database to start fresh

4. "Trial failed":
   - Optuna will skip failed trials and continue
   - Check logs for error messages
   - Fix issue and resume study

5. "Out of memory":
   - Reduce batch_size (popsize) temporarily
   - Or use smaller model/instances for testing
   - Check for memory leaks in optimizer implementation

APPENDIX C: SEARCH SPACE DESIGN THEORY
---------------------------------------

Log-scale vs Linear:

- Use log-scale when:
    * Parameter spans multiple orders of magnitude (0.01 to 1.0)
    * Effect is proportional to relative change (e.g., learning rates)
    * Small values are as important as large values

- Use linear when:
    * Parameter spans single order of magnitude (0.7 to 0.95)
    * Effect is proportional to absolute change (e.g., probabilities)
    * Uniform sampling makes sense

Integer vs Float:

- Use int for:
    * Truly discrete parameters (population size, memory length)
    * When decimal values are meaningless

- Use float for:
    * Continuous parameters (F, CR, sigma)
    * When any value in range is valid

Categorical vs Ordinal:

- Use categorical for:
    * Unordered choices (strategies, initialization methods)
    * Boolean flags

- Could use ordinal for:
    * Ordered discrete choices (but int is usually better)
    * Example: small/medium/large → int values 1/2/3

Conditional Parameters:

- Some parameters only apply with certain choices
- Example: mutation_low, mutation_high only if use_adaptive_mutation=True
- Optuna handles this via conditional suggestions in objective function

Search Space Size:

- Total combinations = product of cardinalities
- Example: 4 strategies × 10 F values × 10 CR values = 400 combinations
- With 50 trials, sampling ~12.5% of space
- TPE learns which regions are promising and focuses there

Constraints:

- Handle constraints in objective function
- Example: Ensure mutation_low < mutation_high
- Invalid trials can return inf or raise exception (Optuna will skip)

APPENDIX D: PARAMETER INTERACTION ANALYSIS
-------------------------------------------

Some parameters interact strongly:

1. F (mutation) and CR (crossover):
   - High F + High CR: Maximum diversity, very explorative
   - High F + Low CR: Aggressive mutation, conservative inheritance
   - Low F + High CR: Conservative mutation, aggressive inheritance
   - Low F + Low CR: Minimum diversity, very exploitative

2. Strategy and F:
   - 'best' strategies prefer lower F (avoid instability)
   - 'rand' strategies work well with higher F (need diversity)

3. sigma0 and restarts (CMA-ES):
   - High sigma + many restarts: Thorough global search (expensive)
   - Low sigma + few restarts: Fast local search

4. Population size and time limit:
   - Large popsize: Fewer iterations within time limit
   - Small popsize: More iterations but less diversity per iteration
   - With fixed popsize=600, this is not tunable

5. diff_padding_num and adaptive parameters (EvoX):
   - Higher padding adds diversity, may compensate for conservative F/CR
   - Lower padding requires well-tuned F/CR for good performance

After tuning, analyze parameter importance plots to identify:
  - Most critical parameters (focus manual tuning here)
  - Interacting parameters (2D contour plots)
  - Independent parameters (can be fixed to defaults)
